# Installable app and offline play

[Back to project guide](PROJECT-GUIDE.md)

blockplaySG installs to a home screen or desktop and plays without a network.
Nothing about the game changed: this is a manifest, four icons and a service
worker that keeps the build on the device.

## Installing

| Platform | How |
| --- | --- |
| Chrome, Edge, Brave (desktop and Android) | The **Install** button in the header, or the browser's own install control. |
| Safari on iOS/iPadOS | Share → **Add to Home Screen**. Safari has no install event, so the header button does not appear. |
| Firefox (Android) | Menu → **Install**. |

The header button only exists while the browser is offering an install: it
appears on the `beforeinstallprompt` event, disappears once the prompt is spent
or the app is installed, and is absent when the app is already running
standalone. `src/lib/pwa.ts` holds that state in a small store created at import
time, because the browser fires the event before React has mounted.

The installed window is `standalone` with the dark `#17231e` title bar the site
already declared as its theme colour. In-game fullscreen (F, or the fullscreen
button) still works on top of that.

## What is cached, and when

`dist/sw.js` is generated by `scripts/service-worker-plugin.mjs` from
`src/sw/service-worker.ts` after the app bundle exists, so it can name that
build's hashed files.

| Cache | Holds | Filled |
| --- | --- | --- |
| `blockplay-shell-<version>` | the page at `/`, the JS and CSS chunks, the manifest and icons — about 1.6 MB | At install |
| `blockplay-media` | Scene geometry, weapon models, the Encik voice pack | The first time each file is used |
| — | `/api/*` | Never |

The split is deliberate. The shell is what makes the app open at all, so it is
paid for once at install. The media under `public/` is another ~10 MB, and an
install should not download nineteen districts' worth of assets for a player who
opens two; it accumulates as you play. The companion API is never cached,
because a cached answer would make an unreachable backend look like a working
one.

`<version>` is a hash of the precached file list. Those names carry Rollup's
content hashes, so the cache name changes when the build changes and stays put
when only a doc moved.

Routing lives in `src/lib/sw-policy.ts`, away from worker globals so it can be
tested (`src/lib/sw-policy.test.ts`):

- **Navigations** to a client-side route are answered from the cached shell.
  Paths that are real files — `/connection-check.html`, the `/audio/encik/`
  listening page — are passed to the network instead, or they would be replaced
  by the game.
- **Precached build output** is served cache-first; it is immutable by name.
- **Everything else same-origin** is cache-first into the media cache, which is
  trimmed to 320 entries oldest-first.
- **Other origins** (Google Maps, OpenAI voice), non-GET requests and ranged
  media requests are passed straight through. The Cache API cannot answer a
  range request with a 206, so caching those would break audio seeking.

### The shell is cached as `/`, not `/index.html`

This one cost a production outage, so it is worth stating plainly. **A response
that arrived through a redirect cannot answer a navigation request** — the
browser refuses it and reports a network error — and the Cache API remembers
that flag across a `put`.

Cloudflare's asset server redirects `/index.html` to `/`. Precaching the shell
under that name therefore stored a response with `redirected: true`, and every
load after the first — the ones the worker answers — failed with
`net::ERR_FAILED` until the visitor cleared site data. The first load always
looked fine, because the worker is not yet controlling the page.

Two things prevent it now: the shell is fetched and stored under `/`, the URL a
navigation actually asks for and the manifest's `start_url`; and
`withoutRedirect()` rebuilds any redirected response before it is cached or
served, so a host that redirects differently cannot reintroduce the fault.
`routeFor` also decides navigations before consulting the precache list, so
`/?room=abc` gets the shell rather than missing an exact-URL lookup.

On activation the worker deletes older shell caches, and drops media whose
filename carries no content hash — a rebuilt `scene.json` or `.glb` can change
under the same URL, while the voice pack's hashed filenames are safe to keep
across deployments.

## Updates

A new build installs in the background and waits. The page shows **A new version
is ready** with a Reload button rather than swapping the running game's code:
the worker only calls `skipWaiting()` when that button asks it to, and the page
reloads on the `controllerchange` that follows. A tab left open overnight
re-checks for a new worker when it becomes visible again, at most hourly.

Browsers revalidate `sw.js` on their own (the default `updateViaCache: 'imports'`
keeps the worker script out of the HTTP cache), and the Worker deployment serves
it with `Cache-Control: public, max-age=0, must-revalidate`.

## Icons

`pnpm icons` regenerates `public/icons/` from `scripts/make-icons.mjs`, which
draws the three skewed blocks of the header mark and encodes the PNGs with
`node:zlib` — no image dependency for four files. Commit the output.

- `icon-192.png`, `icon-512.png` — rounded square, matching the favicon.
- `icon-maskable-512.png` — full-bleed, mark inside the 80% safe circle, because
  the platform applies its own crop.
- `apple-touch-icon.png` — 180 px square; iOS masks it itself.

## Checking it

```sh
pnpm build
pnpm test          # routing, precache manifest and install-prompt unit tests
pnpm test:pwa      # needs Chrome on --remote-debugging-port=9226
```

`scripts/pwa-smoke.mjs` serves `dist` from its own static server so it can
**stop that server** and reload — the only honest offline test. That server
mirrors Cloudflare where it matters (`/index.html` redirects to `/`, unknown
paths fall back to the shell) and the check clears the origin's storage first,
so its first load really is a first load; both were needed to catch the redirect
bug above, since a kinder test server and a reused browser profile each hid it.

It checks the manifest's fields, decodes every icon it declares at its declared
size, confirms the shell cache holds the build and that its shell is not a
redirect result, reloads once **with the server still running** (the load that
broke), warms a model into the media cache, then with the server stopped
asserts that the district list and the Marina scene still
come up, that a client-side route still resolves, that the warmed model still
loads, that `/api/health` correctly fails, and that nothing reached the (absent)
server.

`pnpm test:cloudflare` additionally checks that the deployment serves `/sw.js`
from the site root — a worker only controls its own directory and below — along
with the manifest and a PNG icon.
